# UI 控件与交互契约 v0.1

状态：有效实施契约
最后更新：2026-09-07

本文档用于防止视觉方案实验与数据库或 Agent 行为悄然分叉。不同布局分支可以移动控件或改变样式，但必须保持下列语义、确认流程和共享操作不变。

## 1. 共享控件契约

| 控件 | 用户可见结果 | 持久化操作 | 确认方式 | Agent 对等能力 |
|---|---|---|---|---|
| 心形图标 | 从详情或集合列表行切换喜欢状态 | `PATCH /api/items/{id}/personal`，传入 `isFavorite` | 本地乐观更新；失败时回滚并提示 | `update_item_preferences` |
| 圆圈 + `行った` | 从详情或集合列表行切换显式去过状态；文字固定，仅通过圆圈空心／实心表达状态 | 同一端点，传入 `hasVisited` | 本地乐观更新；已有 Visit 仍意味着去过 | `update_item_preferences` |
| Edit | 修改标题、描述、收藏阶段 | `PATCH /api/items/{id}` | 保存／取消表单 | `update_atlas_item` |
| 列表删除操作 | 删除地点及其关联私有记录 | `DELETE /api/items/{id}`；内置记录创建 tombstone | 必须显示含地点名称的确认对话框 | `delete_atlas_item`，破坏性操作 |
| 类型筛选 | 显示食物、活动、建筑或全部 | 仅修改 ViewModel 状态 | 无 | 未来映射为结构化搜索筛选 |
| 到访 + 喜欢筛选 | 到访状态与喜欢可独立选择；同时启用时只显示同时满足两个条件的地点 | 仅修改 ViewModel 状态 | 无 | 未来映射为推荐／搜索筛选 |
| 集合列表标题 | 紧凑状态先显示省略号；选中、悬停或键盘聚焦时展开完整标题 | 仅修改 View 状态 | 无 | 无 |
| 集合列表评分 | `マイ` 与食べログ评分放在右侧状态栏，并位于个人状态控件上方 | 读取同一 Item 模型 | 无 | 无 |
| 搜索 | 匹配规范化后的名称、别名、区域、地址、描述和标签 | ViewModel 中的确定性查询 | 无 | Agent v2 中的 `search_atlas` |
| 地图标记 | 选择并聚焦一个地点 | ViewModel 选择状态 | 无 | `focus_atlas_item` |
| Near me | 获取位置并按距离排序 | 浏览器地理位置；不存储当前位置 | 浏览器权限确认 | `find_nearby_atlas_items` |
| Save visit | 新增指定日期的到访；评分、笔记或图片必须提供内容 | `POST /api/journal`；若提供评分，则更新该地点唯一的 PlaceAssessment | 保存回执 | `create_visit` |
| Edit visit | 修正日期／笔记，并可替换或清空持久地点评分 | 通过 ViewModel 调用 `PATCH /api/journal/{id}` | 保存／取消表单 | `update_visit` |
| Delete visit | 删除一条错误 Visit，并重新计算推导出的去过状态 | 通过 ViewModel 调用 `DELETE /api/journal/{id}` | 必须确认 | `delete_visit`，破坏性操作 |
| Journal 筛选 | 组合地点与包含边界的起止日期范围 | 仅 ViewModel 投影 | 清空筛选控件 | 未来结构化 Journal 查询 |
| `マイスコア` | 在详情与列表中和来源评分并列；双击详情数值可编辑或清空 | `PATCH /api/items/{id}/personal` | 乐观更新，失败时回滚 | `set_personal_rating` |

## 2. 评分语义

- `null` 表示未评分；`0` 是一个有效的明确评分。
- 当前 Journal 与行内编辑器默认值为 3；上下按钮按 0.5 递增。
- 手动输入接受任意有限的 0–5 数值；UI、HTTP route、store 与浏览器 Agent 工具都会将其四舍五入到最接近的一位小数。
- 领域层／API 仍独立校验 0–5 的闭区间。
- 评分属于地点的 PlaceAssessment，而不属于某一次 Visit。
- 个人评分与食べログ／Google 评分一起展示，便于直接比较，但在存储中仍是相互独立的值。
- 各张卡片不再重复显示来源核验时间；选中地点详情底部统一显示一次最新核验时间。

## 3. 到访与媒体语义

- 一次 Visit 必须关联地点和日期，并至少包含评分、笔记或图片之一。
- 即使没有图片且笔记为空，只有评分的 Visit 也有效。
- 到访序号按时间推导，用户无需手动输入。
- 一个地点拥有一个持久评分和任意数量的 Visit。
- v1 中，每张上传图片可有一行可选说明文字。
- 一次 Visit 可以只包含图片，同时让备注和评分都为空，但三者全部为空的 Visit 无效。
- 只有当二进制、元数据、关联关系和说明文字都能在刷新后保留，并出现在地图的选中地点详情中时，媒体功能才算完成。

## 4. 删除安全

网页 UI 必须显示地点名称，并说明其 Visit 与个人状态也会被删除。“取消”不得产生任何破坏性结果。“确认”会删除动态记录与个人数据；对于随代码打包的内置条目，tombstone 会防止其再次出现。Agent 删除被标记为破坏性操作，渠道必须在调用前取得用户明确确认。

## 5. 布局分支不变量

三个分支可以在集合列表、选中地点详情和移动端面板的位置上有所不同，但都必须：

1. 导入相同的 `useAtlasViewModel`；
2. 调用相同的浏览器 API client 与服务端路由；
3. 渲染多个地图标记，并允许通过标记选择地点；
4. 默认采用以地图为主的视图，并提供可折叠集合列表；
5. 提供喜欢、去过、编辑以及需确认的删除操作；
6. 保持无障碍名称、键盘焦点与小屏可操作性；
7. 不包含硬编码 demo 记录或仅保存在浏览器中的状态。

### 已实现的对比分支

| 分支 | 展示方式 | 需要评估的取舍 |
|---|---|---|
| `codex/ui-floating-drawer` | 全屏地图、叠加式集合抽屉、浮动的选中地点卡片 | 地图占比最大；较小笔记本屏幕上多个浮层可能互相竞争 |
| `codex/ui-split-sidebar` | 打开集合时变为固定左栏，地图随之重新排版 | 列表浏览最清楚；列表打开时地图宽度较小 |
| `codex/ui-bottom-sheet` | 从底部升起的横向集合托盘 | 快速视觉浏览，方向更适合移动端；打开时会压缩纵向详情空间 |

三个分支均从同一套已经测试的持久化／API／ViewModel commit 分出。两个备选分支只修改展示代码。

分栏侧边栏方案已经选定，并成为主版本默认布局。主构建仍通过同一个实时 API 和数据库保留其他方案，用于回归比较：

- B（默认）：`/` 或 `/?layout=split`
- A：`/?layout=floating`
- C：`/?layout=bottom`

这些 query parameter（查询参数）只选择展示方式；它们不会分叉数据状态，也不会持久保存用户偏好。

## 6. 交互性能契约

- 喜欢和去过控件在同一个交互帧内先更新本地状态，再与持久 API 对账。写入失败时恢复旧值并显示提示。
- Journal 提交会立即乐观显示 Visit；API 写入失败时恢复表单与数据。
- Journal 新增使用客户端 mutation ID 与 D1 原子批次，因此超时重试不会产生重复 Visit 或留下半完成的 assessment。
- Journal 写入等待期间不得禁用无关的地图／地点控件。
- 个人状态变化不得重建地图标记。
- 选择标记时应原地更新标记状态并重新居中，不进行耗时的飞行动画。
- 移动中的地图瓦片表面不得被全画布 CSS filter 或 backdrop blur 覆盖。
- Leaflet 使用渐进式桌面瓦片调度；地图供应商、React View 与标记对账通过 adapter 边界分离。
- 性能预算：交互或主线程任务不得超过 200 ms；帧间隔 p95 小于 50 ms、最大值小于 100 ms；固定 100 ms 测试瓦片下稳定时间 p95 小于 400 ms。关闭 issue 前仍需托管证据。
- 当前 OSM 栅格服务是功能基线，并不承诺达到 Google Maps 级别的矢量渲染效果。服务商评估记录在 GitHub issue #1；托管 Journal 请求耗时分析记录在 issue #2。
