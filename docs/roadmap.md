# Roadmap

## P0 — trustworthy PoC

- Make every confirmed Add immediately visible on the map or in Owner review.
- Preserve catalog ratings when personal ratings are edited.
- Stop requiring fields already supplied by a selected candidate.
- Keep Nearby resolution and route failures explicit and recoverable.
- Test browser and signed Agent API parity.

## P1 — complete browser product

- Add category, signature dishes, Google rating, sources, and reservation evidence to model and UI.
- Unify place-detail editing with Journal visits, notes, photos, and captions.
- Replace standalone Review navigation only if unresolved candidates stay discoverable through an Owner inbox.
- Make Add preview concise while retaining evidence internally.

## P2 — semantic agent backend

- Deploy and live-evaluate the guarded Tabelog-only Research Relay, then enable
  it for Owner canary traffic.
- Extend the current scalar schema only through field-specific contracts for category, dishes, and regional ratings.
- Run real pipeline predictions through the checked-in resolution and enrichment gates before enabling production research.
- Add semantic Nearby over verified saved places and Owner preferences.

## Later

- screenshot-to-place intake;
- conversational Record;
- additional model and map providers;
- public-repository deployment templates;
- multi-user permissions if the product stops being single-owner.
