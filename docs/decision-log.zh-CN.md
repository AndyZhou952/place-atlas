# 决策日志

这是产品与工程决策的轻量索引。重要技术决策另行记录为 ADR（架构决策记录）；尚未确定的问题保持明确开放。

| 日期 | 领域 | 决策／状态 | 理由／后续行动 |
|---|---|---|---|
| 2026-09-05 | 产品 | 私有、单用户、以地图为中心的个人 Atlas | 优先满足 Andy 的日常便利，而不是追求面向大众市场的功能广度 |
| 2026-09-05 | 交互 | 微信是主要采集／指令入口；PWA 是可视化事实来源 | 同时兼顾快速采集，以及优于纯聊天的浏览与编辑体验 |
| 2026-09-05 | 运行时 | 提议：将 OpenClaw 作为可替换的网关／运行时 | 目前最适合微信；但必须通过稳定性与安全性评估；见 ADR 0001 |
| 2026-09-05 | 核心 | 领域 API／数据库不得依赖 Agent harness（承载框架） | 保留数据独立性，并允许未来替换运行时或抽取公开版本 |
| 2026-09-05 | 部署 | 提议：云端产品层 + 本地浏览器采集层 | 实现 24/7 可用，同时不把社交平台登录态／浏览器控制导出到云端；见 ADR 0002 |
| 2026-09-05 | 准确率 | ≥90% 指自动确认结果的精确分店准确率，并允许放弃判断 | 避免在视频信息模糊时静默污染地图数据 |
| 2026-09-05 | 来源 | 分享到 Inbox 是可靠默认入口；`web-access` 为可选能力 | 没有合适且稳定的官方批量 API；采集连接器脆弱且必须可替换 |
| 2026-09-05 | 评测 | 分离领域评测与 harness 评测；样本固定在仓库内 | 避免把渠道／运行时问题与抽取／模型质量混为一谈 |
| 2026-09-05 | 公开版本 | 不属于 v1；但保持便于抽取的接口与配置分离 | 为日后作品集／开源预留空间，同时不拖慢旅居版本 |
| 2026-09-05 | 时间模型 | 核心产品与具体日期无关，采用滚动时间窗口与新鲜度 | 旅行日期影响优先级，而不影响架构 |
| 2026-09-05 | UI 架构 | 在与框架无关的领域 API 之上采用受 MVVM 启发的 View／ViewModel | 获得可测试的 UI 分层，但不把 MVVM 强加给 worker／后端 |
| 2026-09-05 | 旧仓库 | 保持 `food-map` 不变，从零构建新产品 | 旧原型只作为可选产品研究材料，不作为代码或架构基线 |
| 2026-09-05 | 早期评测 | 先做 smoke cases（冒烟样例）；采集链路可用后再跑约定的 30 条校准集 | 大部分来源会明确给出信息；评测不应拖延基础建设 |
| 2026-09-06 | 产品数据 | 移除 demo fixtures（演示夹具）；只允许经过来源核验的记录或明确的待审核候选进入产品 | 避免占位数据被误认为 Andy 的可信地图内容 |
| 2026-09-06 | 持久化 | OpenClaw 之前先完成 D1-backed API，并保持 store 可替换 | 网站与未来 Agent 必须共享唯一持久化事实来源；见 ADR 0003 |
| 2026-09-06 | 名称 | 默认以日文标题展示，可选显示其他名称 | 符合 Andy 的语言偏好，也避免不必要的翻译 |
| 2026-09-06 | 评分 | 食べログ评分与个人评分是相互独立、带日期的事实 | 外部评分会变化，必须保留出处 |
| 2026-09-06 | 采集 | Web Access 是重要的首个采集器，但不是核心领域依赖 | 支持按创作者采集，同时隔离平台／登录脆弱性 |
| 2026-09-06 | 界面归属 | 微信 Agent 是主要采集／操作入口；地图是主要浏览／记忆入口 | 在保留丰富空间记录的同时，避免重复工作流 |
| 2026-09-06 | 个人评分 | 每个 Atlas 条目只有一个可空、持久化评分，与可重复的到访分离 | 美术馆可不评分，重复到访也不应产生相互冲突的地点评分 |
| 2026-09-06 | 到访历史 | 根据 Visit 记录推导到访次数与去过状态 | 防止条目重复和人工状态矛盾 |
| 2026-09-06 | 媒体 | 图片二进制存入对象存储，说明文字／关联关系存入 D1 | 支持持久化照片，同时避免结构化存储膨胀 |
| 2026-09-06 | 过渡 UI | 在 Agent 达成功能一致前保留 Inbox／Journal；之后以地图详情和上下文审核链接替代 | 不过早删除目前唯一可用的写入路径 |
| 2026-09-06 | 评分输入 | 手动输入接受任意有限的 0–5 数值；未来快捷控件按 0.5 递增 | 保留精确个人评分，同时避免触屏控件过细 |
| 2026-09-06 | 个人状态 | 喜欢与去过是两个独立的显式控件；存在 Visit 也意味着去过 | 支持“推荐没去过的地点”和直接纠正状态，同时不滥用收藏阶段字段 |
| 2026-09-06 | 删除 | 删除地点必须经 UI 确认，并删除其关联个人记录；内置基础记录使用 tombstone（删除标记） | 防止被删除的内置记录刷新后重新出现 |
| 2026-09-06 | 地图布局 | 在同一 API／ViewModel 之上评估浮动抽屉、分栏侧边栏和底部面板三个版本 | 展示实验不得分叉产品行为或产生仅存在于浏览器的数据 |
| 2026-09-06 | 地图瓦片 | 实验阶段采用无需密钥的 OpenStreetMap 基线 | CARTO 显示需要 API key；生产瓦片策略仍作为明确的性能任务 |
