# ADR 0004：地点级记忆与渠道边界

状态：已接受
日期：2026-09-06

## 背景

第一版 Journal 对每一次 Visit 都创建一张卡片和一个评分。重复到访因此会复制地点、产生相互冲突的评分，并让固定面板布局不断压缩条目。预期的日常交互同时是以微信为先，而地图主要用于浏览与回忆。

## 决策

1. 每个 Atlas 条目存储一份可空的个人评价。
2. 单独存储可重复的 Visit；到访序号和去过状态由记录推导。
3. 媒体二进制存入 R2 兼容对象存储，说明文字／关联关系存入 D1。
4. 在地图的选中地点详情中统一展示评价、Visit 与媒体，而不是保留永久的 Journal 一级入口。
5. 以微信／Agent 作为主要写入渠道。网页写入保留为上下文备用方式；过渡页面仅保留到 Agent 达成功能一致。
6. 采集审核保持上下文化：当视觉证据需要大屏查看时，由 Agent 发送深链接。

## 后果

- 重复到访不再复制地点身份或个人评分；
- 可选评分适用于美术馆、建筑、活动以及未评分餐饮；
- 推荐筛选可以一致地推导去过／没去过；
- Agent 与网站需要粒度更细的 API，而不能继续只依赖一个 Journal POST；
- 图片支持需要 D1 与对象存储，不能只做成浏览器内预览功能；
- 必须等 Agent 替代入口可用后，才能移除当前导航。
