## Standards
- [一般] `apps/web/features/atlas/atlas-view-model-state.ts:277-309`、`apps/web/features/atlas/atlas-view-model-state.test.mjs:90-133`: 新增的 personal-owned merge 以 `"personalRating" in authoritativeItem`／`"overallComment" in authoritativeItem` 判断服务端真值，但清空评分或总评语时 Application 返回的 `undefined` 会在真实 HTTP JSON 序列化中被省略；成功 settle 因而保留 `catalogBase` 的旧值。独立复现从个人评分 4 开始、发送 `{ personalRating: undefined }` 并让成功 response 经过 JSON round-trip 后，最终 ViewModel 仍为 4；持久状态实际已清空，造成即时 UI 与 reload 不一致。现有 T-07 只测由无评分写入 3.5，恰好避开了这个回归。 → 让 mutation response 或 reducer 显式表达“字段已清空”（例如 nullable closed projection，或按完成 mutation 的 own-property patch 合并），并增加清空个人评分与清空总体评论的真实 HTTP JSON round-trip 回归；同时继续断言 Tabelog、地址、来源等 Catalog facts 不变。
- [一般] `apps/web/product/application/conversation/wechat-catalog-intake-presenter.test.mjs:145-181`、`apps/web/product/application/conversation/project-command-router.test.mjs:397-455`: 测试名声称覆盖全部 Add operation failures，但闭合 failure union 的 `unauthorized`、`forbidden`、`rate_limited` 没有经过 presenter/router contract；现有表驱动只覆盖 `dependency_failure`、`invalid_input`、`unexpected_failure`、`not_found` 与 `conflict`，会掩盖鉴权或限流分支以后重新泄漏 provider/error 原文的回归。 → 枚举 `WechatCatalogIntakeOperationFailureKind` 的每个成员及 `expired` code，逐一断言稳定文案、外层错误映射与原始 secret/provider message 不可见；避免用“all”命名的部分覆盖测试充当闭合证明。
- [建议] `apps/web/app/globals.css:2630-2641`: 新增的手机端 `Evidence details` 是 Review list 的主要交互，但样式只有 `0.65rem` 上下 padding 与 `0.72rem` 字号，现有视觉证据只测水平 overflow，没有记录触控尺寸或自动可访问性结果。 → 在 390px harness 中断言该 summary 及新 CTA 的命中区域至少 44×44 CSS px，并补一次 axe/等价自动检查；若计算高度不足，用 `min-block-size` 或令牌化 padding 扩大命中区域。
## Spec
- [一般] `apps/web/scripts/t02-review-browser-smoke.mjs:19-37,65-81`、`apps/web/lib/server/application/t17-dual-adapter-e2e.sqlite.contract.test.mjs:197-233`: spec 的 production React/CSS 浏览器门要求先经 Add 产生 `committed_needs_review`，再由 Owner Review 读回同一条并证明 anonymous/Public/Map/Nearby 隐藏；当前浏览器 harness 直接把手写 `candidate-render-contract` 注入被拦截的 Review API，而 D1 E2E 虽生成真实候选，却没有调用 Owner Review route/client 或渲染该记录。这两段测试并未闭合，因此 route projection、client decoder 或 UI 接缝断裂时仍可同时全绿。 → 建立同一条持久 fixture 的纵向浏览器/集成门：走 Catalog Intake confirm、以真实 Owner Review route 返回并由 production React 渲染同一 ID，同时核对匿名 `/api/items`、Map 与 Nearby 不可见；用这条真实记录生成 desktop/390px list 截图，五态纯 UI harness 可保留为补充。
- [一般] `docs/user-manual.md:27-31`、`apps/web/features/atlas/atlas-screen.tsx:1408-1455`: 手册声称 Review 页面可检查候选的身份、坐标、Tabelog 与预约信息，但当前页面只显示标题、地址/区域、`Map location` 的 Available/Missing、unknown 字段和 warning；坐标、Tabelog、预约、来源与证据时间均未呈现。手册因此没有按 AC15 描述“当前已实现功能”，Owner 会被引导到一个看不到所述信息的页面。 → 二选一：把手册收窄为页面当前确实展示的摘要与限制，或在不扩张本轮发布能力的前提下把既有 `OwnerReviewCandidateView` 中的这些只读事实真正渲染出来，并为 known/unknown 状态补 contract 与截图。
